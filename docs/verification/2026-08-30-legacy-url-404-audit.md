# Legacy URL 404 Audit

**Author:** Manus AI
**Audit window:** 23–30 August 2026, with the Cloudflare edge-404 detail query covering the available eight-day retention window where permitted.

## Scope and Safeguards

This audit reviews recent Cloudflare HTTP analytics, live route behavior, current source links and published crawl surfaces for outdated partner URLs. It does not change Cloudflare, the customer website, the Partner Portal or Google Ads.

## Evidence Captured

Cloudflare Log Explorer is not included in the current account entitlement, so the audit used the read-only GraphQL `httpRequestsAdaptiveGroups` dataset.[1] The available detailed edge-404 sample contained 71 responses. Fifty used `curl`, four used Headless Chrome, three used explicitly named CCG/Manus audit user agents and four used Googlebot. Ten used other browser user agents. Every sampled 404 had an empty referrer, using Cloudflare's request-referrer dimension.[2]

The most frequent 404 paths were synthetic API probes or known audit checks. The apparently important public-route entries were checked live: the retained portal `/partners`, `/partners/apply` and `/partners/login` routes all return HTTP 200; apex and www `/get-quote` return HTTP 200; and all old apex `/trade-partners*` and `trade.` paths now return 308 to the retained portal.

## Soft-404 Discovery

Cloudflare edge status alone does not reveal React soft 404s because the customer Pages application can return HTTP 200 before rendering its `Page Not Found` component. Live browser checks confirmed two uncovered aliases:

| URL | Edge status | Rendered result |
|---|---:|---|
| `https://www.concreteconceptsgroup.com/trade-partners` | 200 | `Page Not Found | Concrete Concepts Group` |
| `https://concreteconceptsgroup.com/partners` | 200 | `Page Not Found | Concrete Concepts Group` |

These routes are not covered by the current rule, which scopes `/trade-partners*` to the apex hostname and covers all paths only on `trade.concreteconceptsgroup.com`.

## Classification

| Evidence class | Requests | Assessment |
|---|---:|---|
| `curl` checks | 50 | Audit/test traffic, not customer navigation |
| Headless Chrome checks | 4 | Automated verification traffic |
| Named CCG/Manus audit agents | 3 | Explicitly labelled verification traffic |
| Googlebot | 4 | Temporary `/partners` failures during one hour; the route is now healthy |
| Other browser agents | 10 | Five malformed iPhone copies of the old path, four same-hour portal checks and one legacy asset/probe path |

All 71 sampled edge 404s had an empty referrer. There is therefore no evidence of a live website, search result, advertising destination or third-party page repeatedly linking customers to another broken URL. Most failures were generated by the recent investigation itself or by automated probing.

The seven-day likely-alias query did expose two **soft 404** route families that deserve consideration even though they do not register as edge 404s:

| Candidate | Seven-day evidence | Current behavior | Recommendation |
|---|---|---|---|
| `www.concreteconceptsgroup.com/trade-partners*` | Two requests, both `curl`; no referrer | HTTP 200 but renders the CCG 404 page | Add to the existing legacy Trade Partners redirect scope for hostname symmetry |
| `concreteconceptsgroup.com/partners*` and `www.concreteconceptsgroup.com/partners*` | Apex `/partners` had one iPhone request and one labelled verification request; no referrer | HTTP 200 but renders the CCG 404 page | Consider a narrowly scoped alias redirect to the retained portal because the director selected that portal as the sole partner experience |

The first candidate is higher confidence because it is the exact `www` counterpart of an already approved retired route. The second is semantically appropriate and low risk, but its observed demand is minimal.

## Routes That Should Not Be Redirected

The following entries are not legacy portal aliases: `/get-quote` is the protected customer funnel and is currently healthy; `/referral` is an active customer-site route; the portal’s `/partners`, `/partners/apply` and `/partners/login` routes are healthy; and `/api/*`, `/media/not-allowed*`, alternate-port and `leads.` paths are tests, scanners or invalid service calls. Redirecting any of these to the portal would mask errors or disrupt a valid customer/service route.

## Validated Recommendation

The safest follow-up is to expand the existing two method-aware redirect expressions rather than add unrelated rules. The proposed scope is:

> Redirect `/trade-partners*` and `/partners*` only when the hostname is `concreteconceptsgroup.com` or `www.concreteconceptsgroup.com`, and continue redirecting every path on `trade.concreteconceptsgroup.com`.

This preserves the existing 308 behavior for GET/HEAD and 302 behavior for other methods through the same Single Redirect ruleset.[3] A local scope contract passed for the five intended alias cases and explicitly preserved apex/www `/`, `/get-quote`, `/referral`, `/lp/retaining-wall-brisbane` and the retained portal hostname. Direct production checks confirmed all protected routes currently return HTTP 200.

| Priority | Alias family | Reason |
|---:|---|---|
| 1 | `www.concreteconceptsgroup.com/trade-partners*` | Exact missing hostname counterpart of the already retired legacy route; currently a soft 404 |
| 2 | Apex and www `/partners*` | Natural shorthand for the director-selected portal; currently a soft 404, but observed demand is only one unlabelled iPhone request plus one audit request |

No production change was made during this audit. The evidence supports adding both alias families as one small revision to the existing ruleset, but the first is the only clearly missing counterpart. The second is a preventative convenience redirect rather than a response to meaningful traffic.
